# Hardware notes — the campaigns reported in the paper

Conditions of the FP16 campaign (`logs/icra2027_final/`) and the INT8 campaign (`logs/icra2027_int8/`). Values marked *declared* were confirmed by the author and could not be read back from the logs; values marked *not recovered* are stated as missing rather than inferred. Every measurement directory also carries its own `provenance` block with the same queries.

- **Jetson module / SKU / RAM:** NVIDIA Jetson AGX Orin Developer Kit, reported by `/proc/device-tree/model`. Exact SKU and RAM size *not recovered* from the container.
- **Carrier board:** the Developer Kit carrier.
- **JetPack / L4T:** L4T R36.4.4, kernel 5.15.148-tegra, aarch64, GCID 41062509, dated 2025-06-16.
- **Container image or environment, and its digest:** a JetPack 6 environment image, with the repository root bind-mounted into it. Image digest *not recovered*.
- **TensorRT / CUDA / cuDNN / PyTorch:** TensorRT 10.3.0.30-1+cuda12.5, CUDA runtime 12.6 with `nvcc` 12.6.68, cuDNN 9.3.0.75, PyTorch 2.5.0a0+872d972e41.nv24.8, torchvision 0.20.0, Python 3.10.12, numpy 1.23.5, onnx 1.21.0, pycocotools 2.0.11, OpenCV 4.11.0. ROS 2 Jazzy is installed in the environment but is outside the measured boundary.
- **`nvpmodel` mode:** NVIDIA 50 W mode (*declared*). `nvpmodel -q --verbose` was **not available inside the container** and the manifests record the failed query. The mode was not measured back from the logs.
- **Clock policy:** `jetson_clocks` **disabled** (*declared*); `jetson_clocks --show` likewise failed inside the container. Telemetry shows CPU frequencies varying mostly between 729 and 1497 MHz during the runs, which is consistent with clocks left unlocked. No script changed clocks or power mode.
- **Fan / heatsink / ambient:** stock Developer Kit cooling, default fan policy. Junction temperature observed at roughly 45.9–47.4 °C during the energy tests, which is not a complete throttling audit. Ambient temperature *not recorded*.
- **CPU affinity and concurrent processes:** no `taskset` applied. Host pre-processing, decoding and NMS run single-threaded. Stages were run one at a time; no deliberate concurrent workload was present. Background system load *not characterized*.
- **Power rail selected, units and scope:** profile `agx-orin`, integrating the sum of `VDD_GPU_SOC`, `VDD_CPU_CV` and `VIN_SYS_5V0` as **module power** in watts. `VDD_CPU_CV` already includes DLA and PVA; `VIN_SYS_5V0` already includes the DDR rail, which is therefore not counted twice. This is not a wall-plug measurement and excludes the carrier, peripherals and power supply. `tegrastats` was copied from the host to `/tmp/tegrastats-paper` because it is not present inside the container; sampling interval 100 ms, timestamped on arrival with the host monotonic clock. Sensor-to-host delay *not calibrated*.
- **COCO:** official val2017 images and `instances_val2017.json`, installed with `tools/experiments/datasets/download_coco_val2017.sh` under `logs/datasets/coco/` on the target. The evaluator reads the COCO JSON directly, with no conversion to YOLO label format. train2017 was used only for the training described below, on the x86 workstation, not on the target.
- **Stock checkpoint:** *not recovered*. `logs/yolo11n.onnx` (SHA-256 `a771561a8a897283e0454caa7951a23de3494169b65ec7842094e021aec68f17`) is the export that every stock engine was built from, and it is consistent across the calibration manifests and build commands, but the identity, version and hash of the upstream `yolo11n.pt` it came from were not preserved. Any stock-versus-adapted difference therefore mixes architecture, training budget and checkpoint provenance.
- **Adapted checkpoint:** as built, SHA-256 `417967ac4a0af77f4a4e1f1f31ba4e31b38775853fa7393f0f8824f2a3511535`, 2,615,696 unfused parameters, recorded date 2026-08-14, Ultralytics version 8.4.48. Exported to an ONNX with SHA-256 `2712fe1182428d45a3dbf4c00de596507a79333dcd1f4c9d0791c61d7c29fcca`. The copies distributed as `weights/yolo11-dla-n.pt` and `weights/yolo11-dla-n.onnx` are those artifacts with the recorded local paths redacted; see [`../../../docs/BUILD.md`](../../../docs/BUILD.md).
- **Adapted training:** COCO train2017, 500 epochs, batch 32, 640×640, seed 0, 8 workers, AMP, `freeze=None`, `nbs=64`, `optimizer=auto`, base LR 0.01, `lrf=0.01`, weight decay 5×10⁻⁴, three warm-up epochs, linear decay, mosaic closed for the last ten epochs; HSV 0.015/0.7/0.4, translate 0.1, scale 0.5, fliplr 0.5, MixUp and copy-paste disabled. Initialized from `yolo11n.pt` by intersecting the state dictionaries on name and shape and loading non-strictly, with no QKV remapping and no frozen-backbone stage. Run on the x86 CUDA workstation container, not on the Jetson. The configuration was extracted from the checkpoint itself into `tools/paper/analysis/checkpoint_training.json`; the optimizer identity (MuSGD, momentum 0.9, 3× LR on selected classification-head groups) is a **reconstruction** from the archived Ultralytics revision `3f2711b10e21eedf4e2efaa907c1322d844ea2d7`, not a stored optimizer state.
- **Fields not recovered, stated explicitly:** container image digest; module SKU and RAM; ambient temperature and background load; the original `nvpmodel`/`jetson_clocks` query output from a privileged shell; the stock checkpoint's identity and hash; the original `coco-bbox.yaml` dataset descriptor and the exact shell command of the training run; hashes of the historical checkpoint→ONNX→engine chain predating the registration (present hashes identify the artifacts **as registered**, and no earlier provenance is claimed retroactively).
