# The audited record

Every published accuracy, latency and energy value, in machine-readable form, with the SHA-256 of the raw artifact each one was computed from. The raw artifacts are campaign output under the untracked [`../logs/`](../logs/README.md); this directory is what stays behind when they do not, and it is what lets a future re-run be checked against what was reported.

| File | Contents | Regenerated by |
| --- | --- | --- |
| `precision_results.json` | the eight configurations across FP16 and INT8 — accuracy, engine latency, application latency, module energy — plus the SHA-256 of each of the eight campaign CSVs they were read from | `run.py collect-results` |
| `engine_summary.csv` | audited FP16 engine summary: 20,167 timing samples, engine sizes, DLA loadables, GPU and reformat node counts | `run.py audit` |
| `layer_profile.csv` | per-layer FP16 profile of the stock fallback and strict engines | `run.py audit` |
| `fp16_audit.json` | the full raw-log audit behind both of the above | `run.py audit` |
| `checkpoint_training.json`, `.csv` | training configuration and the 500-epoch validation history, read back from the checkpoint, with its SHA-256 | `run.py extract-checkpoint` |
| `model_verification.json` | deterministic CPU verification of the export: ONNX operator counts, output shapes, decoder and ONNX Runtime agreement | `run.py check-model` |
| `audits/` | long-form evidence, model and precision audits, preserved verbatim | — |

The number-by-number map from each of these to the value it supports is [`../docs/RESULTS.md`](../docs/RESULTS.md); the provenance, the reuse decisions and the limitations are in [`../docs/PROVENANCE.md`](../docs/PROVENANCE.md).

## Checking the record

`collect-results` re-reads the campaign summaries and re-records their hashes, so with a campaign present under `logs/` the file regenerates identically:

```bash
python tools/experiments/run.py collect-results
git diff --stat analysis/precision_results.json     # empty if the campaign is the one reported
```

Without a campaign the recorded hashes are still usable on their own: they identify the exact files a re-run has to produce to be comparing like with like.

`run.py audit` additionally writes its figures to `analysis/figures/`, which is not tracked.

## What is not here

The manuscript. Its sources, its tables, its figures and its PDF are submitted through the conference system and are not part of this repository, which carries only what is needed to reproduce and audit the experiment.
